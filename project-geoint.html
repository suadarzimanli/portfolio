Overview

What this project does

Analysts filter ACLED events by type, region, county, period and actors, and open any place on the map to read every event recorded there — ACLED geocodes most events to town centres, so a single point in Warsaw holds 1,132 events. A forecast view gives each county’s expected events next month as the average of the three latest complete months, shown beside those three months and the method’s measured accuracy. Light and dark themes on desktop and phone; the paper evaluates the forecast against seven alternatives.

Research questions

What I set out to answer

  • How can an event dataset be presented so that a user moves from a national overview to an individual event record — on desktop and phone — while every forecast stays traceable?
  • What spatial and temporal structure does Poland’s event record show, and what does it imply for forecasting?
  • How accurately do simple and learned methods predict next-month county counts when all use the same information?
  • How much do evaluation choices — months without events, information sets, metrics — change the ranking of methods?

Key findings

What the study showed

  • Among methods that predict activity, differences are small: the Random Forest’s RMSE is 1.35 against 1.43 for the app’s moving average, but the county-bootstrap interval of the difference includes zero, and the moving average wins on a 6-month window.
  • With 85% of county-months empty, mean absolute error rewards predicting no activity at all — RMSE and count-aware scores are needed.
  • The evaluation design mattered more than the method: dropping empty months and giving methods different information made the same Random Forest look 30% better; with the same information, errors on active months were equal.
